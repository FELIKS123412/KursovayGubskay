## 1. Назначение и параметры индивидуального варианта

Консольная программа анализирует телеметрические временные ряды трёх инфраструктурных узлов, вычисляет производный показатель динамики $Q[i]$, находит локальные аномалии и регистрирует инциденты по правилу большинства.

| Характеристика | Значение по варианту 9 |
| :--- | :--- |
| Контролируемые узлы | `DSK` (диск), `NET` (сеть), `API` (шлюз API) |
| Формат входных данных | Формат `В` (`компонент,время,значение`), разделитель — запятая |
| Тип последовательности | Тип `6`: у одного узла возможны несколько замеров на одном отсчёте; учитываются все измерения |
| Производный показатель $Q$ | Логарифм отношения: $Q[i] = \ln\left(\dfrac{X[i]}{X[i-k]}\right)$ |
| Базовые параметры варианта | $k = 3$, $L = 1.0$, $D = 10$ |
| Правило состояния узла | Локальная аномалия: $Q[i] > Q[i-1] \land Q[i] > Q[i+1]$ $\Rightarrow$ `АНОМАЛИЯ`, иначе `НОРМА` |
| Правило инцидента | Большинство присутствующих на отсчёте узлов находятся в состоянии `АНОМАЛИЯ` |
| Структура `Incident` | `typedef struct { int time; int type; int first; int second; } Incident;` |

Исходная контрольная строка телеметрии за 5 отсчётов (17 измерений):

## 2. Математическая модель и обработка недопустимых операций

1. **Расчёт показателя $Q[i]$:**
   $$Q[i] = \ln\left(\frac{X[i]}{X[i-k]}\right), \quad i \ge k$$
   - При $i < k$ пара $X[i-k]$ отсутствует (`CALC_NO_PREV`), расчёт пропускается, статус измерения — `НОРМА`.
   - При $|X[i-k]| < 10^{-6}$ фиксируется ошибка деления на ноль (`CALC_ZERO_DIV`, вывод `ОШИБКА (/0)`), статус — `ОШИБКА`.
   - При $\frac{X[i]}{X[i-k]} \le 0$ (нулевое значение $X[i]$ либо разные знаки пары) логарифм не определён — фиксируется ошибка области определения (`CALC_BAD_ARG`, вывод `ОШИБКА (ln<=0)`), статус — `ОШИБКА`.
   - При нечисловом значении (`NaN`/`Inf`) фиксируется `CALC_NAN_VAL` (`ОШИБКА (NaN)`), статус — `ОШИБКА`.
2. **Классификация локальной аномалии:**
   - Выполняется вторым проходом после вычисления всех $Q[i]$ для ряда.
   - Крайние элементы ($i = 0$ и $i = \text{len} - 1$), а также элементы, у которых хотя бы один сосед ($i - 1$ или $i + 1$) не имеет корректного значения $Q$, не сравниваются (исключён выход за границы массива) и получают статус `НОРМА`.
   - Если `Q[i] > Q[i-1] && Q[i] > Q[i+1]`, измерение помечается как `АНОМАЛИЯ`.
3. **Логическое правило инцидента (большинство):**
   - Для каждого отсчёта $t = 1..\text{max\_tick}$ итоговое состояние узла определяется функцией `node_status_at_tick()`: если хотя бы одно измерение узла на отсчёте $t$ аномально, узел считается проблемным на отсчёте $t$.
   - При наличии трёх узлов на отсчёте булево выражение инцидента имеет вид:
     $$\text{Incident}(t) = (A \land B) \lor (A \land C) \lor (B \land C)$$
     где $A \equiv (S_{\text{DSK}}(t) = \text{АНОМАЛИЯ})$, $B \equiv (S_{\text{NET}}(t) = \text{АНОМАЛИЯ})$, $C \equiv (S_{\text{API}}(t) = \text{АНОМАЛИЯ})$.

## 3. Организация данных и модульная структура

Вся программа находится в файле [KursovayGubskay/Source.c](KursovayGubskay/Source.c) без глобальных переменных. Вместо разрозненных массивов применены перечисления (`NodeId`, `CalcCode`, `NodeStatus`, `DataSource`, `MenuCommand`) и структуры:

```c
typedef struct {
    int tick;
    float value;
    float q;
    CalcCode code;
    NodeStatus status;
} Sample;

typedef struct {
    const char* tag;
    Sample items[SERIES_CAP];
    int len;
} NodeSeries;

typedef struct {
    int time;
    int type;
    int first;
    int second;
} Incident;
```

Все три узла хранятся в массиве `NodeSeries nodes[NODE_COUNT]` (`0` — `DSK`, `1` — `NET`, `2` — `API`), что позволяет обрабатывать их единым циклом без дублирования кода.

**Основные функции:**
- `init_nodes`, `fill_variant_preset`, `read_manual_telemetry`, `ask_step_k` — инициализация, загрузка 17 замеров варианта 9, ручной ввод с валидацией и настройка шага $k$;
- `evaluate_log_ratio` — безопасный расчёт $\ln(X[i]/X[i-k])$ с кодом результата;
- `classify_sample` — проверка локальной аномалии с контролем границ и соседей;
- `process_node_series` — двухпроходный расчёт одного узла;
- `node_status_at_tick`, `majority_rule`, `detect_incidents` — агрегация состояния на отсчёте и заполнение журнала `Incident`;
- `render_banner`, `render_menu`, `render_raw_series`, `render_node_table`, `render_timeline_summary`, `render_incident_table` — табличный вывод в консоль.

## 4. Алгоритм работы программы и блок-схема

### Алгоритм работы программы (КТ2)

1. **Инициализация:** вызвать `init_nodes(nodes)` для обнуления структур узлов `DSK`, `NET`, `API`, задать параметры по умолчанию (`step_k = 3`, `source = SRC_EMPTY`, `analyzed = 0`) и вывести заголовок программы (`render_banner()`).
2. **Главный цикл меню (`do-while`):** отобразить текущую панель состояния и список команд (`render_menu()`), считать номер команды `cmd` с проверкой корректности ввода и `EOF`, затем выполнить выбранное действие через `switch`:
   - **Команда `[1]` (`ask_step_k`):** запросить новый шаг сравнения `k` в диапазоне `1..99`, при корректном вводе обновить `step_k`, сбросить флаг `analyzed = 0` и при необходимости вывести предупреждение о нехватке измерений.
   - **Команда `[2]` (`fill_variant_preset`):** загрузить все 17 измерений контрольного набора варианта 9 (7 замеров для `DSK`, по 5 для `NET` и `API`, упорядоченных по отсчётам `1..5`), установить `source = SRC_VARIANT9`, сбросить `analyzed = 0` и вывести исходные ряды (`render_raw_series()`).
   - **Команда `[3]` (`read_manual_telemetry`):** запросить количество отсчётов `n` (`1..100`), построчно считать тройки значений `DSK NET API` с валидацией ввода, записать их в `nodes`, установить `source = SRC_MANUAL`, сбросить `analyzed = 0` и вывести введённые ряды.
   - **Команда `[4]` (расчёт и вывод отчёта):** проверить, что данные загружены (`source != SRC_EMPTY`), после чего для каждого узла выполнить `process_node_series()` в два прохода:
     1. *Проход 1 (вычисление $Q$):* для $i < k$ отметить пропуск (`CALC_NO_PREV`), для $i \ge k$ вызвать `evaluate_log_ratio(X[i], X[i-k])` с проверкой конечности чисел, деления на ноль ($|X[i-k]| < 10^{-6}$) и области определения логарифма ($X[i]/X[i-k] > 0$), подсчитать число ошибок.
     2. *Проход 2 (поиск локальных аномалий):* для каждого измерения вызвать `classify_sample()`, проверив границы массива ($0 < i < \text{len}-1$), корректность обоих соседних $Q[i-1]$, $Q[i+1]$ и условие $Q[i] > Q[i-1] \land Q[i] > Q[i+1]$.
     Затем вызвать `detect_incidents()` — для каждого отсчёта $t = 1..\text{max\_tick}$ получить агрегированное состояние каждого узла через `node_status_at_tick()`, проверить правило большинства `majority_rule()` и при срабатывании записать структуру `Incident { time, type, first, second }`. Вывести таблицы по узлам (`render_node_table()`), сводку по отсчётам (`render_timeline_summary()`), число ошибок и журнал инцидентов (`render_incident_table()`).
   - **Команда `[5]`:** при наличии данных и выполненного расчёта вывести журнал инцидентов (`render_incident_table()`).
   - **Команда `[6]`:** при наличии данных вывести загруженные исходные ряды (`render_raw_series()`).
   - **Команда `[0]`:** завершить работу программы.

## 5. Ручной контрольный расчёт

Упорядоченные по отсчётам измерения варианта 9:
- **`DSK` (7 измерений):** `(1: 45.5), (2: 48.3), (2: 46.0), (3: 46.5), (4: 47.0), (4: 49.3), (5: 52.9)`
- **`NET` (5 измерений):** `(1: 55.6), (2: 53.6), (3: 57.0), (4: 55.0), (5: 53.0)`
- **`API` (5 измерений):** `(1: 33.9), (2: 33.1), (3: 32.4), (4: 31.6), (5: 30.9)`

### Проверка при $k = 3$ (базовый параметр варианта)
- `DSK`: №4 $\ln(46.5/45.5) = +0.02174$, №5 $\ln(47.0/48.3) = -0.02728$, №6 $\ln(49.3/46.0) = +0.06928$, №7 $\ln(52.9/46.5) = +0.12895$ $\rightarrow$ локальных пиков нет (`НОРМА`).
- `NET`: №4 $\ln(55.0/55.6) = -0.01085$, №5 $\ln(53.0/53.6) = -0.01126$ $\rightarrow$ крайние значения без пары соседей (`НОРМА`).
- `API`: №4 $\ln(31.6/33.9) = -0.07026$, №5 $\ln(30.9/33.1) = -0.06878$ $\rightarrow$ `НОРМА`.
- **Итог:** инцидентов нет (`0`).

### Проверка при $k = 2$
- `NET`: №3 $+0.02487$, №4 **$+0.02578$** (`АНОМАЛИЯ`: больше $+0.02487$ и больше $-0.07276$), №5 $-0.07276$.
- `DSK` и `API`: все измерения `НОРМА`.
- **Итог:** проблемный только 1 узел из 3 — правило большинства не срабатывает, инцидентов нет.

### Проверка при $k = 1$ (срабатывание инцидента)
- `DSK` (№4, $t = 3$): $\ln(46.5/46.0) = +0.01081 > -0.04879$ и $> +0.01070$ $\rightarrow$ **`АНОМАЛИЯ`**.
- `NET` (№3, $t = 3$): $\ln(57.0/53.6) = +0.06150 > -0.03663$ и $> -0.03572$ $\rightarrow$ **`АНОМАЛИЯ`**.
- `API` (№3, $t = 3$): $\ln(32.4/33.1) = -0.02137 > -0.02388$ и $> -0.02500$ $\rightarrow$ **`АНОМАЛИЯ`**.
- **Итог:** инцидент на отсчёте $t = 3$ (`type = 1`, `first = 0 [DSK]`, `second = 1 [NET]`).

### Проверка граничных случаев (ручной ввод, 5 отсчётов, $k = 2$)
- `NET` на $t = 3$: $X[i-2] = 0.0$ $\rightarrow$ `ОШИБКА (/0)`.
- `API` на $t = 4$: $X[i] / X[i-2] = 30.0 / (-5.0) < 0$ $\rightarrow$ `ОШИБКА (ln<=0)`.
- `API` на $t = 5$: $X[i] / X[i-2] = 0.0 / 25.0 = 0$ $\rightarrow$ `ОШИБКА (ln<=0)`.

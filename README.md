# Курсовой проект: Контроль облачной инфраструктуры

## Контрольная точка 2 (КТ2) — Модульная структура программы (MVP)

### Назначение и параметры индивидуального задания (Вариант 9)

Разработанная на языке C консольная программа обрабатывает телеметрические ряды трёх узлов облачной инфраструктуры, вычисляет логарифмический показатель динамики $Q$, обнаруживает локальные аномалии и регистрирует инциденты по правилу большинства.

| Параметр задания | Значение (Вариант 9) |
| :--- | :--- |
| Контролируемые узлы | `DSK` (дисковая подсистема), `NET` (сетевая подсистема), `API` (шлюз API) |
| Формат входной записи | Формат `В` (`компонент–время–значение`), разделитель — запятая |
| Тип последовательности | `6` — допустимы несколько замеров одного узла на одном отсчёте (учитываются все) |
| Базовые константы | $k = 3$, $L = 1.0$, $D = 10$ |

> В рамках КТ2 реализованы встроенный контрольный набор (5 отсчётов, 17 измерений) и ручной ввод рядов `DSK NET API` с клавиатуры. Считывание неупорядоченных записей формата `В` из файла относится к следующему этапу (КТ3).

Контрольная строка телеметрии варианта 9:
```text

```

### Расчётная модель и критерии контроля

1. **Показатель динамики $Q$ (логарифм отношения):**
   $$Q[i] = \ln\left(\frac{X[i]}{X[i - k]}\right)$$
   Вычисление проводится для элементов с индексом $i \ge k$ по паре текущее/предыдущее на шаге $k$:
   - для первых $k$ замеров ($i < k$) предыстория отсутствует (`CALC_NO_PREV`), расчёт пропускается, статус — `НОРМА`;
   - при $|X[i - k]| < 10^{-6}$ деление на ноль предотвращается (`ОШИБКА (/0)`), выставляется статус `ОШИБКА`;
   - при $\frac{X[i]}{X[i - k]} \le 0$ логарифм не определён (`ОШИБКА (ln<=0)`), выставляется статус `ОШИБКА`;
   - при получении `NaN`/`Inf` фиксируется ошибка значения (`ОШИБКА (NaN)`).
2. **Оценка состояния узла (локальная аномалия):**
   - Измерение получает статус **«АНОМАЛИЯ»**, если его показатель $Q[i]$ и оба соседних показателя $Q[i - 1]$, $Q[i + 1]$ вычислены без ошибок ($0 < i < \text{len} - 1$) и выполняется:
     $$Q[i] > Q[i - 1] \quad \land \quad Q[i] > Q[i + 1].$$
   - В остальных корректных случаях (включая крайние точки ряда и точки без валидных соседей) выставляется статус **«НОРМА»**; при сбое формулы — **«ОШИБКА»**.
3. **Условие регистрации инцидента (правило большинства):**
   На отсчёте $t$ узел считается проблемным, если хотя бы один его замер на этом отсчёте имеет статус `АНОМАЛИЯ`. Инцидент фиксируется, когда в проблемном состоянии находится большинство присутствующих на отсчёте узлов (для трёх узлов — не менее двух):
   $$\text{Incident}(t) = (S_{\text{DSK}}[t] \land S_{\text{NET}}[t]) \lor (S_{\text{DSK}}[t] \land S_{\text{API}}[t]) \lor (S_{\text{NET}}[t] \land S_{\text{API}}[t]),$$
   где $S_c[t] \equiv (\text{status}_c[t] = \text{АНОМАЛИЯ})$.

### Представление данных

В программе не используются глобальные переменные; состояния и коды операций описаны перечислениями (`NodeId`, `CalcCode`, `NodeStatus`, `DataSource`, `MenuCommand`), а телеметрия и журнал инцидентов хранятся в статических массивах структур (`SERIES_CAP = 100`, `INCIDENT_CAP = 100`):

```c
typedef struct {
    int tick;
    float value;
    float q;
    CalcCode code;
    NodeStatus status;
} Sample;

typedef struct {
    const char* tag;
    Sample items[SERIES_CAP];
    int len;
} NodeSeries;

typedef struct {
    int time;
    int type;
    int first;
    int second;
} Incident;
```

Индексация узлов в полях `first` и `second`: `0` — `DSK`, `1` — `NET`, `2` — `API`.

## 1. Описание алгоритма и блок-схема

### Порядок работы программы

1. При старте инициализируется массив узлов `nodes[3]` (`init_nodes`), устанавливается шаг по умолчанию $k = 3$, пустой источник данных (`SRC_EMPTY`) и признак отсутствия расчёта (`analyzed = 0`), выводится шапка программы (`render_banner`).
2. Запускается основной цикл `do-while`, в котором отображается панель текущего режима и список команд (`render_menu`), считывается команда `cmd` (с защитой от некорректного ввода и `EOF`) и выполняется ветвление `switch`:
   - **`[1]` — изменение шага $k$ (`ask_step_k`):** ввод целого $k \in [1; 99]$, сброс флага расчёта и вывод предупреждения, если длины рядов не хватает для предыстории или оценки локальной аномалии.
   - **`[2]` — загрузка набора варианта 9 (`fill_variant_preset`):** заполнение всех 17 измерений (7 для `DSK`, по 5 для `NET` и `API`, упорядоченных по $t = 1..5$) и печать рядов (`render_raw_series`).
   - **`[3]` — ручной ввод (`read_manual_telemetry`):** ввод числа отсчётов $n \in [1; 100]$ и считывание троек `DSK NET API` с повторным запросом при ошибке формата.
   - **`[4]` — анализ динамики и отчёт:** при наличии данных для каждого узла выполняется двухпроходная функция `process_node_series`:
     - *1-й проход:* пропуск первых $k$ элементов и расчёт $Q[i]$ функцией `evaluate_log_ratio` с учётом `/0`, $\ln(\le 0)$ и `NaN`;
     - *2-й проход:* определение статуса каждого измерения функцией `classify_sample` без выхода за границы массива.
     Затем `detect_incidents` агрегирует состояния узлов на каждом отсчёте (`node_status_at_tick`), проверяет `majority_rule` и заполняет массив `incident_log`. В консоль выводятся таблицы по узлам, сводка по отсчётам, счётчик ошибок и журнал инцидентов.
   - **`[5]` — просмотр журнала инцидентов (`render_incident_table`):** повторный вывод найденных инцидентов после выполненного расчёта.
   - **`[6]` — просмотр исходных рядов (`render_raw_series`):** отображение загруженной телеметрии.
   - **`[0]` — завершение работы.**

### Сценарий 1: базовый шаг $k = 3$

- **`DSK`:** для №1–3 расчёт пропускается (`НОРМА`); далее №4 $\ln(46.5/45.5) \approx +0.02174$ (крайний слева из вычисленных $\rightarrow$ `НОРМА`), №5 $\ln(47.0/48.3) \approx -0.02728$ (`НОРМА`), №6 $\ln(49.3/46.0) \approx +0.06928 < +0.12895$ (`НОРМА`), №7 $\ln(52.9/46.5) \approx +0.12895$ (крайний справа $\rightarrow$ `НОРМА`).
- **`NET`:** №1–3 пропуск (`НОРМА`); №4 $\ln(55.0/55.6) \approx -0.01085$ (`НОРМА`), №5 $\ln(53.0/53.6) \approx -0.01126$ (`НОРМА`).
- **`API`:** №1–3 пропуск (`НОРМА`); №4 $\ln(31.6/33.9) \approx -0.07026$ (`НОРМА`), №5 $\ln(30.9/33.1) \approx -0.06878$ (`НОРМА`).
- **Инциденты:** `0` (локальных аномалий не выявлено).

### Сценарий 2: переменный шаг $k = 2$

- **`DSK`:** $Q$ для №3..7 равны `+0.01093`, `-0.03798`, `+0.02151`, `+0.05847`, `+0.11826` — локальных пиков нет (`НОРМА`).
- **`NET`:** №3 $+0.02487$, №4 ($t = 4$) $\mathbf{+0.02578}$ (строго больше $+0.02487$ и $-0.07276$ $\rightarrow$ **`АНОМАЛИЯ`**), №5 $-0.07276$.
- **`API`:** №3..5 равны `-0.04526`, `-0.04638`, `-0.04740` (все `НОРМА`).
- **Инциденты:** `0` (аномалия только у одного узла из трёх — условие большинства не выполняется).

### Сценарий 3: переменный шаг $k = 1$ (проверка инцидента)

- **`DSK` (№4, $t = 3$):** $\ln(46.5/46.0) \approx \mathbf{+0.01081} > -0.04879$ и $> +0.01070$ $\rightarrow$ **`АНОМАЛИЯ`**.
- **`NET` (№3, $t = 3$):** $\ln(57.0/53.6) \approx \mathbf{+0.06150} > -0.03663$ и $> -0.03572$ $\rightarrow$ **`АНОМАЛИЯ`**.
- **`API` (№3, $t = 3$):** $\ln(32.4/33.1) \approx \mathbf{-0.02137} > -0.02388$ и $> -0.02500$ $\rightarrow$ **`АНОМАЛИЯ`**.
- **Инцидент на $t = 3$:** зарегистрирован (`type = 1`, `first = 0 [DSK]`, `second = 1 [NET]`).

### Сценарий 4: граничные случаи (`/0` и $\ln(\le 0)$ при $k = 2$)

| Узел | Отсчёт $t$ | Пара $(X[i], X[i-2])$ | Причина ошибки | Результат программы |
| :---: | :---: | :---: | :--- | :---: |
| `NET` | 3 | $(40.0,\ 0.0)$ | Нулевой знаменатель $X[i-2] = 0$ | `ОШИБКА (/0)` |
| `API` | 4 | $(30.0,\ -5.0)$ | Отрицательное отношение $-6.0 \le 0$ | `ОШИБКА (ln<=0)` |
| `API` | 5 | $(0.0,\ 25.0)$ | Нулевое отношение $0.0 \le 0$ | `ОШИБКА (ln<=0)` |

## 3. Программная реализация

Код проекта расположен в файле [KursovayGubskay/Source.c](KursovayGubskay/Source.c) и структурирован по модулям:
- **Вычисления и контроль ошибок:** `evaluate_log_ratio` (проверка конечности, `/0`, $\ln(\le 0)$ и расчёт $Q$).
- **Анализ рядов:** `classify_sample` (правило локальной аномалии с защитой границ), `process_node_series` (двухпроходный расчёт узла).
- **Поиск инцидентов:** `node_status_at_tick`, `majority_rule`, `detect_incidents`.
- **Управление данными и параметрами:** `init_nodes`, `fill_variant_preset`, `read_manual_telemetry`, `ask_step_k`, `longest_series_len`, `flush_stdin_line`.
- **Интерфейс и форматирование таблиц:** `render_banner`, `render_menu`, `render_raw_series`, `render_node_table`, `render_timeline_summary`, `render_incident_table`, `status_caption`, `node_tag_by_id`.
